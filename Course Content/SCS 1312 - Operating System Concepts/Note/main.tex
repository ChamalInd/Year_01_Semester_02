\section{Interrupts (IVEC - Interrupt Vector)}
\begin{figure}[h]
	\centering
	\includegraphics[width=0.4\textwidth]{images/img-03.png}
\end{figure}

\begin{itemize}
	\item Interrupts are signals generated by IO devices like keyboard and mouse or the timer. These devices are connected to the CPU using interrupt lines.
	\item IVEC register is a type of register which contains the memory location of the starting address of the interrupt handlers first instruction which is stored with the OS.
	\item When an interrupt signal is received the address is IVEC is copied into the PC, which makes the instruction in IR to jump to that location in memory which contains the OS. This helps to prevent an application from hogging the CPU.
	\item If any keyboard or mouse interruption does not occur, the application may run forever hogging all the hardware. To prevent this the timer makes an interruption in regular time periods.

\section{Booting Process}
\begin{itemize}
	\item Just when the computer is turned on, memory and all the registers contain some random numbers, since they are all binary devices (must contains 0 or 1).
	\item So at the start, CPU is executing some random instructions. To prevent this PC is hardcoded to some memory location which is on the ROM (ROM is non-volatile memory. Unlike RAM it's data aren't lost after losing electricity). 
	\item The instructions they run now are the BIOS stored in the ROM. All these instructions are executed with the highest privilege.
	\item In real x86 architecture, the PC is hardcoded to a memory address which is 16 bytes below the highest memory address. This 16 bytes contains a jump instruction to jump the PC to the start of the ROM. This can help to deal with different ROM sizes in different computers.
	\item At the start computer runs the POST (Power On Self Test) program stored in the BIOS, which check whether all the hardware devices are attached and is working properly. 
	\item Next it reads the first sector of the hard disk to the RAM which usually contains a boot sector. After loading the data PC is jumped to the starting address of that copied data in the RAM (the Boot Call), after that the CPU keeps executing and loading the next boot sector until the booting process is done.
\end{itemize}

\subsection{Master Boot Record (MBR)}
\begin{itemize}
	\item Consider a hard disk with sectors containing 512 bytes of data.
	\item The first 446 bytes will contain the Boot Code, the next 64 bytes will contain the partition table and the last 2 bytes will contain the magic number which indicates that the given sector is a boot sector (0x55AA). 
	\item[] \textbf{EXTRA:} In linux, the kernel uses magic bytes to decide how to run executables and the file command identifies the files by magic number. The extension doesn't matter in here. 
	\item[] Ex: for Java class files $\rightarrow$ CAFEBABE
	\item[] Ex: for bash scripts $\rightarrow$ \#!/bin/bash
\end{itemize}
